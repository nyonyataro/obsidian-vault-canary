# Vault Canary 手動テスト計画

削除テストは必ず捨てVaultで行ってください。唯一の実データVaultを対象にしないでください。

## Desktopの基本確認

1. `npm ci`と`npm run check`を実行する。
2. `main.js`、`manifest.json`、`styles.css`をテストVaultの`.obsidian/plugins/vault-canary/`へ配置する。
3. Community pluginsでVault Canaryを有効化する。
4. Obsidianが日本語の場合、設定画面が日本語で表示されることを確認する。
5. 表示言語をEnglishに変更し、プラグインを再読み込みして英語表示になることを確認する。
6. `Set current state as baseline`または`現在のVault状態を基準値に設定`を実行する。
7. `Check vault now`または`Vaultを今すぐ確認`を実行し、減少なしの通知を確認する。

## ファイル数の警告

1. `Minimum file drop`を3にする。
2. 小さいテストファイルを3つ用意して基準値を設定する。
3. 3つのファイルを手動で削除する。
4. debounce後に警告が表示されることを確認する。
5. 設定画面の基準値が削除後の小さい状態に変わっていないことを確認する。
6. 3ファイルを復元し、手動チェックで警告が解消されることを確認する。

## 警告状態の保持

1. 警告を発生させる。
2. 1〜2ファイルだけ復元して手動チェックする。
3. 「まだ基準値より小さい状態を確認中」という通知が出ることを確認する。
4. すべて復元するか、バックアップ確認後に明示的に新しい基準値を設定する。

## Markdown数の警告

1. `Minimum Markdown drop`を2にする。
2. Markdownノートを2つ以上含めて基準値を設定する。
3. Markdownノートを2つ削除する。
4. Markdownノートの減少を示す警告を確認する。

## 容量の警告

1. 大きめの捨て添付ファイルを追加する。
2. 基準値を設定する。
3. `Storage size drop (%)`を、添付ファイル削除で超える値にする。
4. 添付ファイルを削除し、容量減少の警告を確認する。

## 変更ファイルの警告

1. 大きめの捨て添付ファイルを追加して基準値を設定する。
2. パスを変えずに添付ファイルを小さい内容へ置き換える。
3. debounce後に容量減少の警告を確認する。

## 除外フォルダ

1. `Ignored/`などのフォルダを作り、捨てファイルを入れる。
2. 設定の除外フォルダへ`Ignored`を入力する。
3. 基準値がクリアされることを確認する。
4. 新しい基準値を設定する。
5. `Ignored`内のファイルを削除しても警告されないことを確認する。

## 起動猶予

1. Startup delayを30秒以上にする。
2. プラグインを再読み込みする。
3. 猶予中に作成・削除を行っても自動警告されないことを確認する。
4. 猶予後に確認が行われることを確認する。
